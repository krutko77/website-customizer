## 2026-08-20 (вечер, вторая итерация) — Яндекс.Карты: исправлена атрибуция cookie, документы приведены к факту

**Исправлена ошибка собственного аудита.** Отчёт от 20.08 приписывал
Яндекс.Картам четыре cookie (`is_gdpr`, `is_gdpr_b`, `pi`, `yashr`) —
вывод был сделан по разнице наборов cookie между `contacts.html` и
остальными страницами, без изоляции источника. Контрольный эксперимент
(три прогона с блокировкой разных хостов) это опроверг:

| Прогон | Cookie |
|---|---|
| Полная загрузка `contacts.html` | 16 |
| Блокировка хостов карт (`maps.yandex`, `yastatic`, `hdrc`) | **те же 16 — ни одна не исчезла** |
| Блокировка `mc.yandex.ru` | 8 |
| Блокировка всего яндексового, кроме карт | **0** |

**Яндекс.Карты не ставят ни одной cookie.** Все 16 принадлежат Метрике:
8 собственных (`_ym_*`, `mdd`, `yabs-sid`, `ymex`, `yuidss`) и 8
общеяндексовых, появляющихся при синхронизации Метрики с доменом
`yandex.ru`. Основание требовать упоминания Карт в документах —
**передача IP-адреса** (плюс User-Agent и Referer) при запросе тайлов,
а не установка cookie; IP по позиции РКН относится к ПДн, поэтому
п. 1 ч. 1 ст. 14 152-ФЗ применим независимо от cookie.

Также уточнено: карта загружается **сразу после нажатия «Принимаю»**,
без клика по заглушке. До согласия и при отказе — 0 запросов к хостам
карт, 0 cookie. Гейтинг работает.

**Разбор документов и правки владельца.** По ходу проверки владелец
правил Политику и Соглашение четырежды за день: 07:05 (Карты добавлены

## 2026-08-13 — Фикс: иконка MAX полностью чёрная в Firefox
- По сообщению пользователя обнаружена ещё одна проблема, не связанная
  с messenger-consent: иконка MAX в шапке сайта в Firefox отображалась
  сплошным чёрным пятном (в Chrome — нормально)
- Диагностировано через анализ живого `img/icons/icons.svg`: символ
  `#max` (в отличие от остальных простых одноцветных иконок в этом же
  спрайте) устроен сложно — внутри `<symbol>` вложен ещё один `<svg>` с

  белый path со значком чата
- Root cause: Chrome резолвит внутренние id-ссылки (`clipPath`,
  вложенный `<use>`) даже когда сам символ вызван через внешний
  `<use xlink:href="icons.svg#max">`; Firefox — нет, из-за чего
  clipPath считается пустым и PNG не рисуется, остаётся только чёрная
  заливка
- Фикс: не чинить хрупкий SVG-спрайт, а заменить иконку на обычный
  `<img>` с готовым PNG (`max-icon.png`, 120×120 для чёткости на
  retina при отображении 40×40 CSS-px) — получен рендером того же
  символа `#max` в Chromium (там clipPath резолвится верно) через
  Playwright и экспортом в PNG, визуально идентичен тому, что уже
  видно в Chrome
- Патч: `sites/es-trans-ru/max-icon-fix/` (PNG + README с инструкцией
  по замене разметки `<svg><use></use></svg>` → `<img>`, CSS менять не

- Проверено рендером иконки с реальным CSS-классом сайта через
