## Ключевые решения

**D-005 · `declare(strict_types=1)` в первой строке, `require` через
`__DIR__`.** После первой выкладки `sendmail.php` все три формы отдавали
**HTTP 500 с пустым телом** на любой запрос — заявки не уходили ни в почту,
ни в базу примерно час. Причина нашлась только после включения логов:

```
PHP Fatal error: strict_types declaration must be the very first statement
in the script ... sendmail.php on line 3
```

В патче `declare` стоял на строке 18 после шапки-комментария — синтаксически
законно. При заливке шапка потерялась, `declare` оказался на строке 3 с
пустой строкой перед ним, а это PHP запрещает безусловно.

Исправлено двумя правками: `declare` перенесён в первую строку вместе с
тегом (`<?php declare(strict_types=1);` — уехать теперь не может физически),
и `require` PHPMailer + `setLanguage()` переведены на `__DIR__`. Второе —
потому что лог показал `sapi_apache2.c`: сайт под Apache, где рабочая
директория при `require` не совпадает с папкой скрипта; до этой ошибки
просто не дошло.

**Пароли в чат не присылать.** Пользователь дважды прислал реальные пароли
(почта, БД) — заменены плейсхолдерами в рабочем файле, объяснено, что это
тот же вектор утечки, которым был скомпрометирован исходный пароль.
Отдельно отмечено: новый пароль почты структурно повторяет старый
(`es-trans#2025` → аналогичный шаблон) и потому угадываем.

## Подводные камни

**Логи на Timeweb выключены по умолчанию.** `access_log` и `error_log` —
панель → Логи → тумблеры по домену, файл появляется в `~/<домен>/`.
Без них HTTP 500 непрозрачна: тело пустое, в `access_log` только код
ответа. В этой сессии — три итерации гаданий против одной строки лога.
**Включать до выкладки, а не после.**

**Файлы для клиента заливать файлом, а не вставкой в редактор.** Конструкции,
чувствительные к позиции (`declare`, BOM, пустая строка перед `<?php`),
ломаются при копировании через буфер. Именно так формы и легли 25.08.

**Относительные `require` в патчах не использовать** — целевое окружение
(Apache/FPM, рабочая директория) заранее неизвестно. Только `__DIR__`.

**Тестировать на версии PHP клиента.** На es-trans.ru **PHP 7.4**, локальный
стенд был 8.2. По ходу сессии я ошибочно заподозрил стрелочную функцию
`fn()` как причину 500-й — версия 7.4 её поддерживает, гипотеза отпала.

**В панели Timeweb две записи `es-trans.ru`** — «Старый сайт (Европа)» с
доменами на PHP 7.4 и вторая без доменов на PHP 8.2. Живой сайт — первая.
При проверках убеждаться, что смотрите нужную.

**Мои собственные ошибки этой сессии** (чтобы не повторить): объявил шаг 2
закрытым, увидев таблицу в дереве и не проверив её содержимое — а в ней была
одна колонка; дважды неверно истолковал скриншоты phpMyAdmin. Вывод: при
