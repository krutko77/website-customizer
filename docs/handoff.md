## Как устроена память проекта

Весь контекст проекта живёт в четырёх файлах. У каждого — одна роль.
Читай их **в этом порядке**:

| # | Файл | Отвечает на вопрос | Как меняется |
|---|------|--------------------|--------------|
| 1 | [project-brief.md](./project-brief.md) | **Что** это за проект и **зачем** | Редко (меняется суть проекта) |
| 2 | [state.md](./state.md) | **Где мы сейчас** и **что делать дальше** | Постоянно — это «живой снимок» |
| 3 | [changelog.md](./changelog.md) | **Что уже сделали** (по датам) | Только дописывается вниз |
| 4 | [decisions.md](./decisions.md) | **Почему** так, а не иначе | Только дописывается вниз |

Плюс [../CLAUDE.md](../CLAUDE.md) — инструкции по стеку, деплою и правилам работы.

**Правило, которое держит всё это в актуальном состоянии:**
после каждого осмысленного шага мы обновляем `state.md` + дописываем
`changelog.md` и **коммитим в git**. Поэтому история проекта = история
коммитов, а текущее положение дел всегда в `state.md`. Подробнее — в
разделе «ЖУРНАЛ ПРОЕКТА И КОММИТЫ» в `CLAUDE.md`.

## Быстрый старт для входящей нейронки

1. Прочитай 4 файла выше по порядку.
2. Глянь последние коммиты — это лента того, что реально делалось:
   ```bash
   git log --oneline -20
   ```
3. Если нужно увидеть, что менялось в конкретном шаге:
   ```bash
   git show <hash>
   ```
4. Посмотри, какие скиллы доступны — это основной инструментарий проекта:
   ```bash
   ls .claude/skills/
   ```
   Описание каждого — в [architecture.md](./architecture.md).
5. Возьми первый пункт из раздела «Следующие шаги» в `state.md` — и продолжай.

**Дата снимка:** 2026-08-12
**В одном предложении:** Cookie-баннер для es-trans.ru полностью готов, задеплоен клиентом и проверен на живом проде (accept/decline/reload — 6/6 каждый сценарий), плюс исправлены два бага по пути (мёртвая IIFE в `script.js`, раздутая высота баннера на мобильной версии) — фича закрыта, активных задач по ней нет.
**Что работает прямо сейчас:** 35 скиллов в `.claude/skills/` — правка вёрстки, дизайн и темы (`frontend-design`, `theme-factory`, `ui-ux-pro-max`) и процесс (`superpowers`, `/log`, `/end`). Браузерная автоматизация (`playwright-skill`, `webapp-testing`) проверена и многократно использована для реальных проверок на живом проде. Cookie-баннер на `https://es-trans.ru/` работает end-to-end: показывается при первом визите, блокирует Яндекс.Метрику до согласия, корректно обрабатывает «Принимаю»/«Отказаться», решение сохраняется в `localStorage`, на мобильных экранах отображается компактно. Репозиторий на GitHub: `github.com/krutko77/website-customizer`, ветка `main`, upstream-трекинг работает штатно.
**Что в процессе / недоделано:** Ничего активного по cookie-баннеру. Общие хвосты проекта: `project-brief.md` заполнен частично (нет разделов доступы/ключи, дизайн), стек не выбран — `package.json` без зависимостей, серверной части нет, отзыв старого GitHub PAT `ghp_...ye1EkTdP` не подтверждён.
**Где живёт прод (URL / SERVER_ID):** Не задеплоен (в рамках этого репозитория). Целевой сайт клиента — https://es-trans.ru/ (клиент сам держит исходники в отдельном Gulp-проекте на своём ноутбуке, вне доступа этой среды, и сам выкладывает правки — у нас нет прямого доступа ни к файлам, ни к серверу). VPS: 201.51.4.183, следующий свободный порт был 3004 (сверить перед использованием). `deploy-vps.sh` применим только если появится серверная часть — сейчас он ссылается на несуществующий `src/server.js`.
**Главные подводные камни:** Реальные файлы сайта клиента недоступны для прямого редактирования — все правки готовятся как точный текстовый патч в чате и передаются клиенту, который сам вносит их и пересобирает через Gulp; канонические файлы-эталоны в `sites/es-trans-ru/cookie-banner/` нужно вручную синхронизировать с тем, что реально ушло клиенту. Эта VS Code-сессия подключена через локальный shim-прокси (`ANTHROPIC_BASE_URL=http://172.30.0.1:8190`), не напрямую к аккаунту claude.ai — `/status`/Usage не показывают реальные лимиты подписки. `.env.example` НЕ в `.gitignore` (в отличие от `.env`) — секреты туда класть нельзя. Старый GitHub PAT `ghp_...ye1EkTdP` заменён новым — пользователь должен подтвердить отзыв старого на GitHub. Прямые fetch к github.com заблокированы — работать через `curl`/`git` (обычные внешние сайты, включая es-trans.ru, через `curl` доступны без ограничений). Запись в `.claude/commands/` только через python3.
**Первое, что стоит сделать новому исполнителю:** Прочитать `state.md` → «Следующие шаги» — сейчас там только фоновые хвосты (отзыв старого PAT, донаполнение `project-brief.md`, решение по бэкенду), ждать новую задачу правки от пользователя.
