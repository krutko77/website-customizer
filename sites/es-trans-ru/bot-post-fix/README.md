# Защита от прямого POST в `sendmail.php`

**Сайт:** es-trans.ru
**Дата:** 2026-08-26
**Статус:** патч готов, на прод не выложен
**Меняет:** только `files/sendmail/sendmail.php` (вёрстку и формы — нет)

## Проблема

В журнале согласий обнаружена запись, которую не отправлял человек:

```
id 2 | 2026-08-26 01:23:37 UTC | form-customs | HenryEnush
     | henryMax@mail.ru | IP 168.81.74.37 | page_url: https://es-trans.ru/
```

Улика — **`page_url`**. Он берётся из заголовка `HTTP_REFERER`, то есть со
страницы, где стояла форма. Здесь это главная страница, а форма
`form-customs` открывается **только** с `services-customs.html`. Значит POST
шёл прямо в обработчик, минуя сайт.

**Воспроизведено на живом проде 26.08:**

```bash
curl -X POST https://es-trans.ru/files/sendmail/sendmail.php \
  -d "name-driver=X" -d "tel-driver=+70000000002" -d "agreement=on"
→ {"message":"Данные отправлены!","ok":true}
```

Ни `Referer`, ни `Origin`, ни cookie, ни JS — заявка принята, письмо ушло,
запись в журнале создана.

⚠️ При воспроизведении в базу попали **две технические записи** с телефонами
`+70000000001` и `+70000000002` — это мои проверочные запросы, не заявки.
Удалить вместе с остальными тестовыми (список в `docs/state.md`).

**Почему honeypot не помог.** Он ловит ботов, которые заполняют **все** поля
подряд, включая скрытое `website`. Бот, который шлёт только нужные поля и
ставит `agreement=on`, honeypot просто не видит:

| Сценарий | Сейчас |
|---|---|
| POST без `agreement` | ✅ отклоняется |
| POST с заполненным `website` (honeypot) | ✅ тихо отсекается |
| **POST без `Referer`, без honeypot, с `agreement=on`** | ❌ **принимается** |

## Чем это плохо

Функционально сайт не сломан, и **защита по 152-ФЗ не нарушена** — согласие
на сервере проверяется, POST без `agreement` по-прежнему отклоняется.
Проблема в другом:

1. **Журнал согласий засоряется.** По ч. 1 ст. 9 152-ФЗ таблица `consents` —
   доказательство реальных согласий. Записи ботов делают её менее пригодной
   для этой роли: при запросе субъекта или проверке РКН придётся объяснять,
   откуда в журнале согласия несуществующих людей.
2. **Почта забивается спамом**, и настоящие заявки в нём теряются.
3. **Обработчик — открытый релей для рассылки писем** на `kpv@es-trans.pro`.
   Пока объём мал, но ограничений нет никаких.

Приоритет **🟡 средний**: одна запись за сутки — не авария, но чинить лучше
до того, как поток вырастет.

## Решение

Три проверки, все — в `sendmail.php`, ни одна не трогает вёрстку.

### 1. Проверка `Origin` / `Referer` — основная

Браузер при отправке формы всегда шлёт `Referer` с адресом страницы (а при
cross-origin — ещё и `Origin`). Простые боты их не подставляют.

Отклоняем запрос, если оба заголовка пусты либо ведут на чужой домен.

**Осознанное ограничение:** заголовки подделываются тривиально, поэтому это
защита **от массового примитивного спама, а не от целевой атаки**. Целевую
здесь и не отбить — форма публичная по определению. Задача скромнее: убрать
фоновый мусор из журнала согласий.

**Важно:** ответ боту — тихий «успех», как у honeypot. Если ответить ошибкой,
бот поймёт, что его отсекли, и начнёт подставлять заголовок.

### 2. Ограничение частоты с одного IP

Не более 5 заявок с одного IP за 10 минут. Живому человеку столько не нужно
(даже если он пишет с трёх форм подряд), а рассылку это ограничивает.

Реализовано **на файлах**, без БД: при недоступности базы обработчик обязан
продолжать работать — согласие пишется в `fallback_log`. Если бы лимит жил в
БД, сбой базы снял бы и защиту.

### 3. Минимальное время заполнения формы

Отсекает мгновенные отправки: человек не заполнит форму за 2 секунды.
Требует **скрытого поля с меткой времени** в вёрстке, поэтому вынесено в
опциональный шаг — без правки Gulp-проекта не работает.

⚠️ Метку времени надо подписывать (HMAC), иначе бот подставит любую.
Реализация в `sendmail-timestamp-optional.php`.

## Что выложить

**Минимальный вариант (рекомендую) — только правки 1 и 2.**
Файл `sendmail.php` из этой папки заменяет текущий на сервере. Вёрстка,
Gulp-пересборка и формы **не затрагиваются вообще** — меняется один
PHP-файл на хостинге.

Диффы — в `changes.diff`. Изменения точечные: добавлены две функции и два
блока проверок перед honeypot.

## Файлы патча

| Файл | Назначение |
|---|---|
| `sendmail.php` | обработчик с защитами — **заменяет файл на сервере** |
| `changes.diff` | что именно изменилось относительно `consent-log/sendmail.php` |
| `config-addition.php` | необязательный блок `rate_limit` для `es-trans-config.php` |
| `test-guards.php` | локальный тест защит, 24 проверки |
| `sendmail-timestamp-optional.php` | третий уровень (метка времени с HMAC), фрагменты, не готовый файл |

Настройки лимита **необязательны**: без блока `rate_limit` в конфиге
берутся значения по умолчанию — 5 заявок за 10 минут, каталог
`/config/rate-limit`.

## Что проверено локально

`php sites/es-trans-ru/bot-post-fix/test-guards.php` → **24/24**, провалов нет.

Проверка домена (11 сценариев): пустые заголовки отклоняются, свой домен и
`www` проходят, чужой домен отклоняется, **подделка `es-trans.ru.evil.com`
отклоняется**, мусор вместо URL отклоняется, верхний регистр проходит,
Origin чужой + Referer свой → пропуск (не режем живых).

Лимит частоты (13 сценариев): счёт по каждому IP отдельно, отметки вне окна
не учитываются, **имя файла — хеш, а не IP** (каталог не должен быть списком
адресов посетителей — это тоже ПДн), за прокси Timeweb считается по
`X-Forwarded-For`, а не по адресу прокси. Отказоустойчивость: нет каталога,
лимит 0, нет блока конфига, битый JSON — **во всех случаях запрос
пропускается**, а не отклоняется.

Тест прогнан негативно: если заменить точное сравнение хоста на поиск
подстроки, тест падает на `es-trans.ru.evil.com` (23/24). То есть проверки
действительно что-то проверяют, а не всегда зелёные.

## Порядок выкладки

1. **Сохранить текущий `sendmail.php`** (переименовать в
   `sendmail.php.bak-2026-08-26`) — откат в одно движение.
2. Залить новый `sendmail.php` в `files/sendmail/`.
3. Создать папку для счётчиков лимита **вне `public_html`**, рядом с
   конфигом:
   ```
   /config/rate-limit/     права 700
   ```
   Если папки нет, лимит просто отключается (обработчик продолжит работать —
   см. «Отказоустойчивость»).
4. Прогнать проверку ниже.

## Как проверить

```bash
# 1. Голый POST без Referer — должен вернуть тихий «успех»,
#    но письмо НЕ приходит и записи в базе НЕ появляется
curl -X POST https://es-trans.ru/files/sendmail/sendmail.php \
  -d "name-driver=БОТ-ТЕСТ" -d "tel-driver=+70000000009" -d "agreement=on"

# 2. POST с правильным Referer — проходит как обычно
curl -X POST https://es-trans.ru/files/sendmail/sendmail.php \
  -H "Referer: https://es-trans.ru/vacancy-driver.html" \
  -d "name-driver=ТЕСТ 26.08 не отвечать" -d "tel-driver=+70000000009" \
  -d "agreement=on"

# 3. Rate limit: шестой запрос подряд должен отсекаться
for i in $(seq 1 6); do
  curl -s -o /dev/null -w "%{http_code} " -X POST \
    -H "Referer: https://es-trans.ru/vacancy-driver.html" \
    https://es-trans.ru/files/sendmail/sendmail.php \
    -d "name-driver=RL$i" -d "tel-driver=+70000000009" -d "agreement=on"
done
```

**Главная проверка — регрессия:** после выкладки отправить по одной живой
заявке из каждой формы через браузер (чек-лист
`docs/checklists/live-forms-e2e-check.md`). Если проверка `Referer` окажется
слишком строгой, формы замолчат **тихо** — пользователь увидит «успех», а
заявка не дойдёт. Это худший из возможных отказов, поэтому прогон
обязателен.

## Отказоустойчивость

Принцип: **защита от спама не должна ронять приём заявок.** Настоящая заявка
дороже, чем пропущенный бот.

- Папка для лимита недоступна или не создана → лимит **отключается**,
  обработчик работает.
- Ошибка записи счётчика → запрос **пропускается**.
- `Referer` пуст, но `Origin` верный (или наоборот) → **пропускается**.

Единственный случай отказа — оба заголовка отсутствуют или указывают на
чужой домен.

## Чего патч НЕ делает

- **Не защищает от целевой атаки.** Подставить `Referer` — одна строка в
  скрипте. Против упорного спамера нужна CAPTCHA (например, Yandex SmartCaptcha),
  но она требует правки вёрстки, добавляет внешний скрипт и **сама по себе
  обработчик ПДн** — её пришлось бы вносить в Политику как получателя данных.
  Городить это ради одной записи за сутки преждевременно.
- **Не удаляет уже накопленный мусор.** Запись id 2 и тестовые записи
  удаляются вручную, см. `state.md`.
- **Не трогает форму на главной** — она работает через Битрикс24, у него
  своя защита.

## Что делать, если спам продолжится

Порядок эскалации, от дешёвого к дорогому:

1. Этот патч (заголовки + лимит) — бесплатно, 1 файл.
2. Скрытая метка времени с HMAC — правка вёрстки, `sendmail-timestamp-optional.php`.
3. Yandex SmartCaptcha — внешний сервис, правка Политики и Согласия
   (новый получатель ПДн, п. 1 ч. 1 ст. 14 152-ФЗ).
