# Разовое согласие на Яндекс.Карты — кнопка «Показать карту» при отказе

**Сайт:** es-trans.ru
**Дата:** 2026-08-26
**Статус:** 🟡 готов, **на прод не выложен**.

## Зачем

Кнопка «Показать карту» на заглушке грузила карту **вообще без проверки
согласия**. При сохранённом отказе (`localStorage['es-trans-cookie-consent']
= 'declined'`) клик по ней ставил **11 cookie домена `.yandex.ru`**
(`yandexuid`, `yuidss`, `i`, `pi`, `bh`, `ymex`, `yashr`, `_yasc`, `is_gdpr`,
`is_gdpr_b`, `yabs-sid`) и делал 32 запроса к Яндексу.

Замерено на живом проде 26.08.2026:

| Сценарий | Запросы к Яндексу | cookie | iframe |
|---|---|---|---|
| До выбора | 0 | 0 | нет |
| Отказ, карту не открывали | 0 | 0 | нет |
| **Отказ + клик «Показать карту»** | **32** | **11** | **есть** |
| Принимаю | 36 | 16 | есть |

Разовый показ карты по клику — **сам по себе законное решение**, оно было
заложено в патче `consent-gating-fix` осознанно («посмотреть карту» ≠
«согласиться на аналитику»). Проблема в том, что это согласие **никак не
фиксировалось**: в хранилище оставался `declined`, следа о том, что человек
сам попросил карту, не оставалось, а cookie уже стояли.

По **ч. 1 ст. 9 152-ФЗ** согласие должно быть конкретным, информированным
и **доказуемым** — обязанность доказать его лежит на операторе. Внешне
ситуация выглядела как «пользователь отказался, а трекеры всё равно
загрузились».

## Что изменено

Два файла патча `consent-gating-fix/` (канонические исходники, совпадающие
с продом):

| Файл | Что |
|---|---|
| `cookie-banner.js` | разовое согласие фиксируется, кнопка проверяет состояние, предупреждение при отказе |
| `map-placeholder.css` | стиль `.map-placeholder__warning` |

Полный дифф — в `changes.diff`. Файлы целиком лежат здесь же и готовы к
подстановке в Gulp-проект.

### 1. Разовое согласие фиксируется

Новый ключ **`es-trans-map-consent` в `sessionStorage`** (не в
`localStorage`): согласие действует в пределах вкладки, новый визит — новый
выбор. Общий отказ на аналитику **не переписывается**, Метрика по-прежнему
не поднимается.

```js
function loadMap(container, userInitiated) { … if (userInitiated) grantMapConsent(); … }
```

`userInitiated` выставляется **только** при клике по кнопке на заглушке.
Загрузка по общему `accepted` разовый ключ не пишет — она уже покрыта
записью в `localStorage`.

### 2. Предупреждение перед кликом

При активном отказе на заглушке появляется строка (ключ словаря
`map-placeholder-5`, RU/EN/CN):

> Вы отказались от cookie. Карта загрузится только на это посещение и
> установит файлы cookie Яндекс.Карт.

Без неё разовое согласие не было бы **информированным**. До выбора в
баннере предупреждение не показывается — отказа ещё нет.

### 3. Заглушка обновляется при отказе

Заглушка строится один раз при загрузке, когда выбор ещё не сделан, а
обработчик «Отказаться» её не трогал. Добавлен вызов `initMaps('declined')`
и функция `syncMapWarning()`, которая **дорисовывает предупреждение в уже
существующую заглушку**, не пересобирая её (пересборка сбросила бы
состояние и могла схлопнуть загруженную карту).

### 4. Карта не схлопывается при перерисовке

`initMaps()` теперь учитывает `hasMapConsent()`: если разовое согласие уже
выдано, повторный вызов (например, после смены языка) снова покажет карту,
а не заглушку.

## Подводные камни

**Стенд обязан проверять, что баннер один.** Первая версия теста глушила
прод-баннер переименованием ключа `es-trans-cookie-consent` — баннер при
этом всё равно рисовался, на странице оказывалось **два**, а `querySelector`
брал прод-овский. Тест показывал ложные провалы, пока не выяснилось, что
кликает он не по патчу. В верификаторе стоит проверка `banners !== 1` →
падение с ошибкой: лучше упасть громко, чем намерить ложное «ок».

**`__dirname` в скриптах для `playwright-skill` не работает** — `run.js`
копирует скрипт во временный файл в своей директории. В верификаторе путь
берётся из `PATCH_DIR` с запасным абсолютным вариантом.

**Карта на `contacts.html` уже починена** (25.08, недокументированная
выкладка владельца вместе с `consent-log/`): в `data-map-src` стоит рабочий
URL виджета `/map-widget/v1/?…&source=constructor` с прод-овским ID
`dad8984b…`. Отдельная правка `/maps/` → `/map-widget/v1/`, висевшая с
21.08, **больше не нужна**.

## Что дальше

`es-trans-cookie-consent` (иначе на сайте будет два баннера), и прогнать оба
верификатора по живому сайту.
