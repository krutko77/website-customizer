# Патч: отзыв cookie-согласия («Настройки cookie» в футере)

**Статус:** готов к применению, протестирован локально (19/19 сценариев).
**Дата:** 2026-08-17
**Зачем:** закрывает последнее замечание по коду из аудита 152-ФЗ —
см. `docs/checklists/audit-es-trans-ru-2026-08-17.md`, пункт №4.

---

## Проблема

Сейчас решение пользователя по cookie сохраняется в
`localStorage['es-trans-cookie-consent']` **навсегда**, а интерфейса
«изменить/отозвать» на сайте нет. По требованиям 2026 года отозвать
согласие должно быть не сложнее, чем его дать.

Попутно этим же патчем чинится второй дефект, найденный при проверке:
**баннер не переводился на другие языки**. Ключи `cookie-banner-1…7`
в словаре сайта есть, но функция перевода `je()` в `app.min.js`
отрабатывает один раз при загрузке страницы, а баннер создаётся позже —
поэтому на en/cn версиях он оставался русским (подтверждено Playwright'ом:
на всех трёх языках текст и кнопки были русские). Это ровно тот же баг и
то же решение, что было в `messenger-consent.js`.

---

## Что нужно сделать — 2 правки

### Правка 1. Заменить файл `cookie-banner.js`

Взять `cookie-banner.js` из этой папки и положить вместо текущего
(в Gulp-проекте — исходник, из которого собирается `js/app.min.js`).

Изменения относительно версии на проде:

| Что | Было | Стало |
|-----|------|-------|
| Отзыв согласия | нет | `#cookie-settings-link` сбрасывает решение и показывает баннер |
| Перевод баннера | через `je()`, не срабатывал | свой словарь `TRANSLATIONS` + `localStorage['language']` |
| Cookie при отзыве/отказе | оставались | удаляются (`_ym_*`, `bh`, `yandexuid`, …) |
| Сборка баннера | `innerHTML`-строкой | DOM-методы (как в messenger-consent) |
| Двойной показ баннера | возможен | защита в `showBanner()` |

Логика accept/decline, гейтинг Метрики и Bitrix24-формы **не менялись**.

### Правка 2. Добавить ссылку в футер

В список `footer__list` — на **всех** страницах (см. предупреждение ниже),
после «Договор на оказание услуг»:

```html
<li class="footer__item">
  <a class="footer__link link" href="#" id="cookie-settings-link" data-lang="cookie-banner-8">Настройки cookie</a>
</li>
```

Текст ссылки скрипт проставляет сам по текущему языку — `data-lang`
оставлен для единообразия с остальной разметкой.

## ⚠️ Важно: пересобирать сайт целиком

Попапы и футер **продублированы в разметке каждой страницы**, а не
вынесены в общий include. На прошлой правке форм из-за этого получилась
частичная выкладка: правка попала только в `vacancy-driver.html`, а
5 других страниц остались со старым кодом.

Ссылку в футер нужно добавить на всех страницах, где есть футер:

## Как это работает

1. **Клик по «Настройки cookie»** → `localStorage` очищается, cookie
   трекеров удаляются.
2. Если согласие **было дано** — страница перезагружается. Причина: уже
   запущенную в этой вкладке Метрику из JS не остановить, а после
   перезагрузки она не стартует (согласия нет) и новых cookie не поставит.
3. Если согласия **не было** (или был отказ) — баннер показывается сразу,
   без перезагрузки.
4. Пользователь делает новый выбор — дальше всё как обычно.

Удаление cookie при отзыве принципиально: без него отзыв формальный —
трекер больше не грузится, но его идентификатор посетителя продолжает жить.

## Чек-лист проверки после деплоя

Прогнать в инкогнито:

- [ ] Ссылка «Настройки cookie» видна в футере на всех страницах из списка выше
- [ ] Первый визит → баннер показан
- [ ] «Принимаю» → баннер скрылся, появились cookie `_ym_*`
- [ ] Клик «Настройки cookie» → страница перезагрузилась, баннер показан снова,
      cookie `_ym_*` и `bh` **исчезли**
- [ ] Новый выбор «Отказаться» → cookie не появились, Метрика не стартовала
- [ ] «Отказаться» → «Настройки cookie» → баннер показан **без** перезагрузки
- [ ] Двойной клик по ссылке → баннер ровно один, не дублируется
- [ ] Переключить язык на EN → баннер и ссылка на английском
      («Cookie settings», «I accept», «Refuse»)
- [ ] Переключить на CN → на китайском («Cookie 设置», «我接受», «拒绝»)
- [ ] Форма заявки Bitrix24 по-прежнему появляется после любого выбора
- [ ] Регрессия: до выбора по-прежнему **ноль** внешних запросов и cookie

Локальные тесты (19 сценариев: отзыв после accept/decline, повторный
выбор, двойной клик, локализация на 3 языках) пройдены до передачи —
но на проде перепроверить обязательно, там реальный `app.min.js`.
